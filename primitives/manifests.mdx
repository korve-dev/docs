---
title: "Infrastructure as code"
description: "Export, plan, and apply organization state from TOML, JSON, or YAML."
---

Korve manifests reconcile projects, Git source, automatic scaling limits, and spend limits. The
same versioned contract drives CLI, API, dashboard, and MCP. Version 2 is the default for export and
new files. Version 1 remains available only to read and reconcile legacy manifests.

```yaml
version: 2
organization: acme
projects:
  - name: Storefront
    slug: storefront
    source: { repo: acme/storefront, ref: main }
    scaling:
      minimumReady: 0
      maximumReplicas: 10
      targetConcurrency: 40
    spend:
      monthlyScaleCeilingUsd: 100
```

Korve selects compute placement and machine capacity. You set outcomes: the minimum ready capacity,
the maximum replica count, target request concurrency, and an optional spend ceiling.

```bash
korve manifest export -o korve.toml
korve manifest plan -f korve.toml
korve manifest apply -f korve.toml
```

Format follows the `.toml`, `.json`, `.yaml`, or `.yml` extension. Plans classify actions as create,
update, no-op, deferred, invalid, or orphaned. Apply creates and updates declared resources but does
not delete live resources omitted from the file.

Secrets and object data never belong in a manifest. Plans do not delete undeclared resources.
Dangerous and destructive actions remain human-gated. See the [Manifest
API](/api-reference/manifest).
