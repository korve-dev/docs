---
title: "Managed Postgres"
description: "Provision several named databases per environment, inspect them, and manage credentials safely."
---

A project can have several named Postgres databases in each environment. Choose the SKU and database
region at creation. The shown-once connection string uses a Korve hostname and standard TLS.

```bash
korve databases provision primary --sku db-s1 --region us-east
korve databases list
korve databases show primary
```

Store the connection string immediately as a server-side environment variable. It cannot be fetched
later. Rotation prints a new connection string and invalidates the old password, so update the
application and redeploy as one coordinated change.

```bash
korve databases rotate primary
korve env set DATABASE_URL='postgres://...'
korve deploy
```

The explorer supports schema inspection, cursor-bounded rows, exactly one read-only SQL statement,
cancellation, and metadata-only history. Query results are bounded to 500 rows.

```bash
korve databases schema primary
korve databases rows primary users --schema public --limit 100
korve databases query primary --sql 'select count(*) from users'
korve databases insights primary --limit 25
```

Use [backups](/primitives/backups), [branches](/primitives/database-branches),
[metrics](/primitives/metrics), and the [advisor](/primitives/advisor) before production changes.
See the [Databases API](/api-reference/databases).
