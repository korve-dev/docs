---
title: "Automatic compute and regions"
description: "Understand automatic application scaling and locality for stateful resources."
---

Korve automatically places and scales request-driven web applications and APIs. New projects do not
select a compute mode, machine size, compute provider, or compute region. An idle service can stop
all replicas. The next request starts capacity again.

Use service limits to control availability, capacity, and cost:

```bash
korve projects create --name Storefront --slug storefront
korve services list --project storefront
korve services scaling show <service-id> --project storefront
korve services scaling set <service-id> --minimum-ready 0 \
  --maximum-replicas 10 --target-concurrency 40 --project storefront
korve services scaling events <service-id> --project storefront
```

Databases, caches, and storage still use their own locality catalogs. Never copy a region id from
another resource type. Discover the current catalog with `korve regions`, and see the
[Regions API](/api-reference/regions). See the [Services API](/api-reference/services) for the
web-service contract and workload restrictions.
