---
title: "Quickstart"
description: "Turn a Git repository into a live, linked Korve project with automatic compute."
---

This path creates a project with automatic compute, links the current directory, and queues the first
deployment from Git.

## 1. Create an account and activate billing

Sign in at [korve.dev](https://korve.dev). Provisioning requires active organization billing. Review
the [published rate card](/primitives/budgets-and-usage) before you create the project.

## 2. Install and authorize the CLI

```bash
curl -fsSL https://korve.dev/install.sh | sh
korve login
```

`korve login` opens a browser authorization page and uses OAuth 2.1 with PKCE. Review the organization,
requested role, and exact operation scopes, then approve. See [Agent OAuth](/agents/oauth).

## 3. Create and link the project

Run this from the repository:

```bash
korve projects create --name Storefront --slug storefront \
  --repo acme/storefront --ref main
korve link storefront
```

The create command sends no compute placement or machine-size options. It uses automatic compute
defaults and queues the first deployment. `korve link` writes `.korve.toml` and installs the agent
files for later project-scoped commands.

## 4. Verify the live application

```bash
korve deploys list
korve services list
korve services scaling show <service-id>
korve logs --level error --limit 100
curl -fsS https://storefront.korve.app/
```

If the deployment fails, inspect its complete build log and start a durable operator thread:

```bash
korve deploys get <deploy-id> --json
korve operator create --title "Investigate first deploy" --deployment <deploy-id>
```

Set only the capacity and cost limits that the workload needs. Zero minimum replicas stops idle
compute charges. The public maximum is 20 replicas.

```bash
korve services scaling set <service-id> --minimum-ready 0 --maximum-replicas 10 \
  --target-concurrency 40
korve services scaling events <service-id>
```

## 5. Add infrastructure deliberately

Add only the databases, storage, queues, crons, caches, alerts, access policy, and maintenance policy
the app actually needs. Manage these optional primitives with their CLI or API operations. Public
manifests use version 2 and never expose compute placement. See
[Automatic compute](/primitives/automatic-compute) and
[Infrastructure as code](/primitives/manifests).
