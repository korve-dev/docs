Run `korve <command> --help` for the installed version's complete flags. Add global `--json` for
machine-readable output. Project commands accept `--project <slug|id>` and otherwise use
`KORVE_PROJECT` or `.korve.toml`.

| Area                   | Commands                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Session and bootstrap  | `login`, `logout`, `whoami`, `init`, `link`, `health`, `spec`, `regions`, `completions`                             |
| Organization           | `orgs`, `billing`, `webhooks`, `api-keys`                                                                           |
| Application            | `projects`, `services`, `environments`, `deploy`, `deploys`, `previews`, `env`, `domains`, `access`                 |
| Data                   | `databases`, `branches`, `backups`, `storage`, `buckets`, `caches`                                                  |
| Work                   | `queues`, `crons`                                                                                                   |
| Operations             | `operator`, `maintenance`, `logs`, `analytics`, `metrics`, `speed-insights`, `alerts`, `advisor`, `budget`, `usage` |
| Infrastructure as code | `manifest export`, `manifest plan`, `manifest apply`                                                                |

## Common flows

```bash
# detect, plan, apply, link, and deploy
korve init

# inspect an application
korve deploys list
korve logs --level error --limit 100
korve analytics
korve speed-insights query --device mobile --granularity day

# inspect and bound automatic compute
korve services list
korve services scaling show <service-id>
korve services scaling set <service-id> --minimum-ready 0 --maximum-replicas 10
korve services scaling events <service-id>

# declare and reconcile an organization
korve manifest export -o korve.toml
korve manifest plan -f korve.toml
korve manifest apply -f korve.toml
```

Commands with complex request bodies accept `--data '<json>'` or `--data @request.json`. Prefer a
file for confirmation tokens and secrets so they do not enter shell history.

```bash
korve queues create --data @queue.json
korve crons create --data @cron.json
korve metrics project --data @metrics-query.json
korve backups restore-promote --database primary <restore-id> --data @confirm.json --yes
```

Create/update/delete verbs, accepted body fields, roles, and response shapes are generated from the
same contract as the [API reference](/api-reference/overview). The CLI parity test prevents an
API-key-capable public operation from shipping without its command.
